# Archetype Audit Guide

Read only the sections matching the current subproblems. Apply the interface and numerical checks to every pipeline.

## Universal pipeline interfaces

- Define every stage's inputs, outputs, units, indices, time horizon, and uncertainty.
- Check that preprocessing creates the variables assumed by the model and that model outputs match downstream decision semantics.
- Distinguish problem-provided values, data estimates, literature values, author/team choices, and algorithm hyperparameters.
- Verify counts and dimensions after every filter, join, aggregation, encoding, and decision-vector construction.
- Check whether uncertainty is discarded between prediction, estimation, simulation, and optimization.

## Regression and statistical inference

- Compare sample size with parameter count and residual degrees of freedom.
- Check transformations, residual structure, heteroscedasticity, influence, multicollinearity, parameter signs, significance, and uncertainty intervals.
- Keep variable selection and preprocessing inside the validation split.
- Separate in-sample explanation from prediction and causal claims.

## Forecasting and time series

- Preserve chronological order and use future holdout or rolling-origin evaluation at the required forecast horizon.
- Compare with naive or seasonal baselines; diagnose trend, seasonality, missing periods, stockouts, and regime changes.
- Prevent future covariates, full-series decomposition, or overlapping windows from leaking information.
- Produce prediction uncertainty and propagate it when downstream decisions can change.

## Machine learning and classification

- Establish an interpretable baseline and explicit train/validation/test or nested-CV structure.
- Fit imputation, scaling, PCA, feature selection, resampling, and hyperparameter tuning within folds.
- Audit class support, imbalance handling, calibration, per-class metrics, integer confusion matrices, and repeated splits or seeds.
- For stacking, train upper layers on out-of-fold lower-layer predictions.

## Evaluation and ranking

- Define every indicator, unit, positive/negative direction, normalization, and missing-value rule.
- Justify weighting and test weight sensitivity and rank stability.
- Recompute rankings and check whether a formal ranking model is actually necessary.
- Do not treat same-data ranking agreement as external validation or causality.

## Deterministic optimization, scheduling, routing, and graphs

- Define decision variables, objective, constraints, units, time/state transitions, and feasibility tolerances.
- Map every prose constraint to code and report final constraint residuals.
- Check boundary behavior, integrality, state completeness, event timing, collision/coverage predicates, and graph/path connectivity.
- Compare algorithms only on the same data, objective, constraints, feasible region, and computational budget.
- Call heuristic output `best-found` unless a bound, gap, exhaustive search, or proof supports a stronger claim.

## Robust and stochastic optimization

- Identify uncertainty sources and justify distributions, scenarios, dependencies, and probabilities.
- Define the risk measure and inspect sign, tail, normalization, and confidence level.
- Check scenario coverage and sensitivity to distributional or correlation assumptions.
- Distinguish robust optimization from a few one-at-a-time scenarios.

## Simulation and dynamical systems

- Calibrate parameters or label assumptions; retain analytic special cases, conservation checks, or independent numerical baselines.
- Check time step, integration grid, sample/ray count, event logic, convergence, and scenario coverage.
- Fix and report random seeds, repeat stochastic runs, and summarize distributions rather than one trajectory.
- Do not use data generated by the same simulator as independent validation of that simulator.

## Inverse problems and physical measurement

- Write the forward model and check identifiability, initialization, units, parameter bounds, and residual structure.
- Test forward consistency, noise sensitivity, parameter correlation, and boundary solutions.
- Use synthetic recovery carefully and state when forward and inverse models create an `inverse crime`.
- Seek mismatched simulation, standard specimens, independent instruments, or other external truth when feasible.

## Spatial geometry and coverage

- Check coordinate systems, orientation, scale, geometric predicates, tolerances, boundary inclusion, and finite versus infinite objects.
- Validate simplified collision, visibility, or coverage rules against a small exact or high-fidelity baseline.
- Separate geometric feasibility from route cost and scheduling; verify that spatial approximations preserve all required constraints.

## Numerical sanity checks

Continuously check units, dimensions, ranges, sample and parameter counts, percentages and denominators, inequalities, objective signs, constraints, boundary solutions, and simple arithmetic. Generated code and historical methods are not exempt from these checks.
